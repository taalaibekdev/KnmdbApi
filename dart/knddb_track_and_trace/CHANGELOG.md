# Журнал изменений

Все значимые изменения пакета документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [семантическому версионированию](https://semver.org/lang/ru/).

## 1.0.1

Исправления по результатам тестирования на боевом контуре с тестовыми
организациями (Тест_склад → тест-аптека).

Исправления проверены на **живом тестовом контуре** `https://testndbapi.med.kg/`
с реальными тестовыми организациями: вход, справочник организаций (11 468 записей),
справочник лекарств (3 919 записей), список перемещений и проверка лекарства
по QR-коду. Все операции — только чтение.

### Исправлено
- **КРИТИЧНО: вход не работал из-за лишней области доступа.** SDK запрашивал
  `scope=api offline_access`, а сервер регистрирует только `api`
  (`options.RegisterScopes("api")`). Область `offline_access` в OpenIddict
  разрешена лишь при включённом потоке обновления токена, которого на сервере
  KNMDB нет, поэтому запрос отклонялся **целиком**, ещё до проверки логина
  и пароля: `invalid_request` — «The 'offline_access' scope is not allowed».
  Проверено на живом тестовом контуре. Теперь SDK запрашивает `api`;
  область настраивается через `KnddbClientOptions(scope:)`.
- **`TrackAndTraceStatus.notSpecified` (0)** — добавлено значение, которого нет
  в серверном перечислении, но которое реально приходит в данных. Проверено
  на тестовом контуре: из 3919 препаратов у **3676 (94 %)** статус равен нулю.
  Раньше такие препараты получали неправильный статус по умолчанию.
  Не путайте значение `0` («статус не задан») с `notTracked` (1).

- **Ошибки бизнес-логики больше не выглядят успехом.** Сервер отвечает
  конвертом `{ resultCode, resultMessage, actionResult }` и при ошибке
  бизнес-логики оставляет **HTTP 200** (коды 6022 «упаковка не найдена»,
  6023 «не подходит для продажи» и другие). Раньше SDK пытался разобрать
  конверт как результат метода: поля оставались пустыми, и приложение получало
  «успех» с пустым объектом. Теперь SDK разбирает `actionResult` при
  `resultCode = 0` и выбрасывает `KnddbApiException` при любом другом значении.
- **Понятное сообщение об ошибке на `/connect/token`.** Раньше ошибка сервера
  с HTTP 200 выглядела как «сервер не вернул поле `access_token`». Теперь
  сообщается настоящая причина, код результата и подсказка о вероятной причине.
- **Заголовок `user-agent` отправляется всегда.** Сервер KNMDB записывает его
  в базу данных при входе; без заголовка вход падал с кодом результата 2
  «An error occurred while saving the entity changes». Если приложение не задало
  заголовок, подставляется `Knddb.TrackAndTrace.SDK/1.0`.
- **Даты в запросах больше не содержат времени.** Сервер принимает только
  `yyyy-MM-dd` и отклонял значения вида `2026-03-15T12:00:00` с кодом
  результата 2. Теперь время отбрасывается автоматически для всех полей-дат.
  Поле `lastUpdate` (синхронизация справочника) по-прежнему передаёт полную
  отметку времени.

### Добавлено

- **`KnddbResultCodes`** — все коды результата сервера с константами
  и русскими описаниями: `KnddbResultCodes.describe(6022)`.
- **Свойства исключения:** `resultCode`, `resultMessage`, `resultDescription`,
  `isBusinessError`, `isProductNotFound` (404 или 6022/6039),
  `isProductNotSuitableForSale` (6023).
- **`toString()`** исключения теперь показывает код результата, его расшифровку
  и текст от сервера.

### Тесты

- 13 новых тестов: разбор конверта, ошибки 6022/6023/1/2 с HTTP 200,
  неизвестные коды, заголовок `user-agent` (по умолчанию и свой),
  формат дат без времени. Всего — 65 тестов.

## 1.0.0

Первая публичная версия.

### Добавлено

- **Аутентификация OAuth 2.0:** `signIn`, `signOut`, автоматическое продление
  токена по `refresh_token`, повторный вход по сохранённым учётным данным,
  повтор запроса при ответе `401`.
- **Смена пользователя «на ходу»:** `sessionKey` в `signIn`, `useSession`,
  `useSessionWithCredentials`, вкладываемые области `beginUserScope` /
  `endUserScope`. Один экземпляр клиента обслуживает нескольких пользователей.
- **Все 23 метода Track and Trace API** с типизированными моделями запросов
  и ответов.
- **Контуры:** тестовый `https://testndbapi.med.kg/` (по умолчанию) и боевой
  `https://ndbapi.med.kg/`; выбор через `KnddbEnvironment` или явный `baseUrl`.
- **Сохранение входа между запусками приложения** через `KnddbSessionStorage`;
  восстановление методом `restoreSession`. Пароль на диск не сохраняется.
- **Обработка ошибок:** `KnddbApiException` со статусом, телом ответа,
  разобранным `ProblemDetails`, `traceId` и словарём ошибок валидации;
  вспомогательные признаки `isNotFound`, `isForbidden`, `isBadRequest`,
  `isConflict`, `isTransientFailure`.
- **7 перечислений** с русскими документациями, числовыми значениями сервера
  и терпимым разбором: принимаются и числа, и строковые имена, и
  человекочитаемые названия.
- **Проверка лекарственного средства без авторизации** с готовым вердиктом
  `verificationVerdict` для интерфейса приложения потребителя.
- **52 теста** на сериализацию, работу методов, смену пользователя, обновление
  токена и обработку ошибок.

### Помечено как устаревшее

- `getSupportedQrTypes` и типы `GetSupportedQRTypesResponse`, `QRTypeInfo`
  помечены `@Deprecated`: метод `GET /api/TrackAndTrace/GetSupportedQRTypes`
  исключён из API департамента лекарственных средств. Значение `qrTypeId`
  согласуйте с департаментом и задайте константой в конфигурации приложения.
  Метод и типы будут удалены из пакета, когда окончательно исчезнут из API.
