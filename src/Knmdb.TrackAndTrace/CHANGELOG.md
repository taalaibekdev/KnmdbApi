# Журнал изменений

Все значимые изменения пакета документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версии следуют [семантическому версионированию](https://semver.org/lang/ru/).

## 1.0.1

Исправления по результатам тестирования на боевом контуре с тестовыми
организациями (Тест_склад → тест-аптека).

Исправления проверены на **живом тестовом контуре** `https://testndbapi.med.kg/`
с реальными тестовыми организациями: вход, справочник организаций (11 468 записей),
справочник лекарств (3 919 записей), список перемещений и проверка лекарства
по QR-коду. Все операции — только чтение.

### Исправлено
- **КРИТИЧНО: вход не работал из-за лишней области доступа.** SDK запрашивал
  `scope=api offline_access`, а сервер регистрирует только `api`
  (`options.RegisterScopes("api")`). Область `offline_access` в OpenIddict
  разрешена лишь при включённом потоке обновления токена, которого на сервере
  KNMDB нет, поэтому запрос отклонялся **целиком**, ещё до проверки логина
  и пароля: `invalid_request` — «The 'offline_access' scope is not allowed».
  Проверено на живом тестовом контуре. Теперь SDK запрашивает `api`;
  область настраивается через `KnddbClientOptions.Scope`.
- **`TrackAndTraceStatus.NotSpecified` (0)** — добавлено значение, которого нет
  в серверном перечислении, но которое реально приходит в данных. Проверено
  на тестовом контуре: из 3919 препаратов у **3676 (94 %)** статус равен нулю.
  Раньше такие препараты получали неправильный статус по умолчанию.
  Не путайте значение `0` («статус не задан») с `NotTracked` (1).

- **Ошибки бизнес-логики больше не выглядят успехом.** Сервер отвечает
  конвертом `{ resultCode, resultMessage, actionResult }` и при ошибке
  бизнес-логики оставляет **HTTP 200** (коды 6022 «упаковка не найдена»,
  6023 «не подходит для продажи» и другие). Раньше SDK пытался разобрать
  конверт как результат метода: все поля оставались значениями по умолчанию,
  и приложение получало «успех» с пустым объектом. Теперь SDK возвращает
  содержимое `actionResult` при `resultCode = 0` и выбрасывает
  `KnddbApiException` при любом другом значении.
- **Понятное сообщение об ошибке на `/connect/token`.** Раньше ошибка сервера
  с HTTP 200 выглядела как «сервер авторизации не вернул поле `access_token`».
  Теперь сообщается настоящая причина, код результата и подсказка о вероятной
  причине (заголовок `User-Agent`, формат дат).
- **Заголовок `User-Agent` отправляется всегда.** Сервер KNMDB записывает его
  в базу данных при входе (`AuthorizationController`, поле `UserAgent`); без
  заголовка вход падал с кодом результата 2 «An error occurred while saving
  the entity changes». Если приложение не задало заголовок, подставляется
  `Knmdb.TrackAndTrace.SDK/1.0`.
- **Даты в запросах больше не содержат времени.** Сервер принимает только
  `yyyy-MM-dd` и отклонял значения вида `2026-03-15T12:00:00Z` с кодом
  результата 2. Теперь время отбрасывается автоматически для всех полей-дат;
  день берётся в часовом поясе вызывающей стороны, поэтому дата операции
  не «съезжает» на день назад.

### Добавлено

- **`KnddbResultCodes`** — все коды результата сервера с константами
  и русскими описаниями: `KnddbResultCodes.ProductWithQrCodeNotFound` (6022),
  `KnddbResultCodes.Describe(6022)`.
- **Свойства `KnddbApiException`:** `ResultCode`, `ResultMessage`,
  `IsBusinessError`, `IsProductNotFound` (404 или 6022/6039),
  `IsProductNotSuitableForSale` (6023), `GetResultDescription()`.
- **`KnddbActionResultEnvelope`** — модель конверта ответа (используется SDK
  внутренне, доступна для диагностики).
- **`KnddbClientOptions.DefaultUserAgent`** — значение заголовка по умолчанию.
- `ToString()` исключения теперь показывает код результата, его расшифровку,
  `TraceId` и ошибки валидации.

### Документация

- Раздел «Конверт ответа и коды результата» в `docs/API-REFERENCE.md`:
  формат конверта, полный список кодов, примеры обработки.
- Раздел «Заголовок User-Agent» с объяснением причины ошибки.
- Раздел «Ошибки, найденные при тестировании на боевом контуре»
  в `docs/SCENARIOS.md` и таблица «Если что-то не работает» в README.

### Тесты

- 15 новых тестов: разбор конверта, ошибки 6022/6023/1/2 с HTTP 200,
  неизвестные коды, заголовок `User-Agent` (по умолчанию и свой),
  формат дат без времени. Всего — 69 тестов.

## 1.0.0

Первая публичная версия.

### Добавлено

- **DI-сервис:** `AddKnddbTrackAndTrace(...)` с чтением настроек из конфигурации,
  из делегата или из перечисления контуров.
- **Аутентификация OAuth 2.0:** `SignInAsync`, `SignOutAsync`, автоматическое
  продление токена по `refresh_token`, повторный вход по сохранённым учётным
  данным, повтор запроса при ответе `401`.
- **Смена пользователя «на ходу»:** `sessionKey`, `UseSession`,
  `UseSessionWithCredentials`, вкладываемые области `BeginUserScope` /
  `EndUserScope`. Один синглтон обслуживает нескольких пользователей.
- **Все 23 метода Track and Trace API** с типизированными моделями.
- **Контуры:** тестовый `https://testndbapi.med.kg/` (по умолчанию) и боевой
  `https://ndbapi.med.kg/`; выбор через `KnddbEnvironment` или явный `BaseAddress`.
- **AOT и trimming:** сериализация через источник-генератор `System.Text.Json`,
  без отражения в горячем пути.
- **7 перечислений** с русскими документациями и числовыми значениями сервера;
  конвертер принимает числа, имена членов и человекочитаемые названия.
- **Сохранение входа** через свою реализацию `IKnddbSessionStore`.
- **54 теста** на сериализацию, внедрение зависимостей, работу методов,
  смену пользователя, обновление токена и обработку ошибок.

### Помечено как устаревшее

- `GetSupportedQrTypesAsync` и типы `GetSupportedQRTypesResponse`, `QRTypeInfo`
  помечены `[Obsolete]` (`KNMDB0001`): метод
  `GET /api/TrackAndTrace/GetSupportedQRTypes` исключён из API департамента
  лекарственных средств. Значение `qrTypeId` согласуйте с департаментом
  и задайте константой в конфигурации приложения.
